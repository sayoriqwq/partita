## Projection into Partita

The behavioral body preserves Matt's center of gravity: one user-supplied fixed point and committed three-dot diff; independent Standards and Spec reviewer contexts; repository standards as primary authority over a twelve-smell heuristic floor; citation-bearing findings; explicit no-spec behavior; and side-by-side aggregation with no cross-axis merge, reranking, or overall winner.

The ordered preflight, local spec lookup, complete smell baseline, parallel role briefs, report headings, per-axis totals, and per-axis worst findings preserve the source's supporting mechanics.

Partita changes only the bounded shell: explicit-only Codex entry, Primitive family because no Skill is composed, the one-owner marker/effects contract, one truthful provisional disclosure, read-only local evidence scope with no issue-tracker/setup dependency, immutable provenance, and one final Recall handoff. Reviewer roles and parallelism do not make this a Workflow.

## Case debt and disconfirmation

No real Captain Code Review use yet validates this projection. Evidence that independent axes hide a load-bearing interaction, isolated reviewers recurse or cannot stay independent, cited reports remain materially unreliable, the smell floor conflicts with accepted repository practice, the committed three-dot scope misses the authorized target, or users expect bug hunting would disconfirm part of this shell.

A later explicit `recall` owns reconstruction of the real case and judgment. Recall and provenance never authorize edits. Every patch to this identity-valid Skill MUST be performed through a later explicit `retune`.
